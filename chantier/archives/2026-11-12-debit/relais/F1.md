# F1 — Fichiers partagés et leur fusion prévue

## 1. Fait, critère par critère
1. **Clé de profil.** `controles.fichiers_partages(profil) -> dict[str, str]` (motif -> fusion) est la seule fonction qui lit `fichiers_partages`. Une entrée vaut `{"motif": "...", "fusion": "union" | "git"}` ; sans `fusion`, c'est « git ». Elle ignore sans planter : ce qui n'est pas un objet, une fusion inconnue, un motif absent, vide, pas une chaîne, avec un espace, ou qui commence par `#` ou `!`, et une clé qui n'est pas une liste.
2. **Moteur.** `Moteur._prochaine` appelle `se_chevauchent(t.perimetre, a.perimetre, fichiers_partages(self.profil))`. Une entrée de périmètre couverte par un motif partagé (`motif_partage`) ne retient plus personne ; le reste compte comme avant (`*` retient toujours tout). Test : A [`DECISIONS.md`, `a.py`] et B [`DECISIONS.md`, `b.py`] tournent ensemble avec la déclaration, et B attend sans elle. Testé par `executer` et par `_prochaine` directement.
3. **Plan.** `forme_du_plan(taches, partages=())` passe par la même `se_chevauchent`, y compris pour l'explication (`_premier_recoupement`) : la règle n'est écrite qu'une fois. A et B sont dans la même vague avec la déclaration, dans deux sans.
4. **Union.** Juste avant chaque `git merge` de l'Atelier (`ControlesGit._reglages`), les motifs en « union » sont écrits d'un seul geste dans `.atelier/unions.gitattributes` (`FICHIER_UNIONS`), sous la forme `/<motif> merge=union`. Le fichier est passé à git par `-c core.attributesFile=…`. Rien n'est écrit dans `.git/` et aucun `.gitattributes` n'est commité. Test sur un vrai dépôt : deux tâches parallèles ajoutent chacune une ligne à `DECISIONS.md`, les deux entrent, les deux lignes sont là, sans marqueur.
5. **Conflit en « git ».** Après un refus d'enregistrement, `_enregistrer` appelle `_conflit_a_reprendre`. Si un motif est déclaré en « git » et que le départ n'a pas encore eu de reprise de fusion, il appelle `poser_conflits` (seulement sur `ControlesGit`). Celui-ci refait la fusion dans la copie, la pose sur la branche principale (`git reset` mixte, marqueurs compris) et rend chaque fichier en conflit avec sa nature. Si tous ces fichiers sont déclarés en « git », le refus devient reprenable, et l'ouvrier est repris dans sa session avec `REPRISES["integration"]` et la liste `conflits_en_clair` ; sinon, le chemin d'avant. Le message nomme les fichiers et demande de garder les deux intentions, sans commande git. Ensuite : périmètre, contrôles, vérificateur, nouvel enregistrement. Une reprise de fusion par départ, hors de la borne `REPRISES_PAR_DEPART`. Au-delà de cette reprise, si la session est perdue, sans `poser_conflits` ou sans conflit : le chemin d'avant (copie jetée, départ suivant depuis la branche principale).
6. **Consigne de découpage.** `REGLES_DECOUPAGE` dit qu'un fichier déclaré partagé peut figurer dans le périmètre de plusieurs tâches parallèles (liste dans `chantier/profil.json`) ; les trois règles du fichier commun, et la tâche de raccord, ne valent plus que pour un fichier non déclaré. Un test garde ces phrases.
7. **Sans `fichiers_partages`, rien ne change** : `se_chevauchent` sans motifs, aucun fichier d'attributs, aucun `-c`, aucun conflit repris, consigne de l'ouvrier identique ; `enregistrer` défait toujours une fusion ratée.

## Reprise (après le refus du vérificateur)
1. **Seuls les fichiers déclarés sont repris.** Il faut au moins un motif déclaré en « git », et chaque fichier en conflit doit être couvert par l'un d'eux. Sinon, le chemin d'avant. Tests : profil `{}` avec A [`x.py`] pendant qu'un commit de la branche principale touche `x.py`, puis la variante où `DECISIONS.md` est déclaré mais le conflit porte sur `x.py`. Dans les deux cas : `tentatives == 2`, aucune reprise, pas de marqueur.
2. **Garde contre les marqueurs.** `poser_conflits` note, par tâche, les fichiers rendus avec des marqueurs ; une copie neuve (`preparer`) efface la note. `enregistrer` refuse si l'un d'eux a encore une ligne qui commence par `<<<<<<< ` ou `>>>>>>> `. Le contenu est lu ; un soulignement Markdown `=======` passe. Ce refus ne se reprend pas : le départ a déjà eu sa reprise de fusion, donc chemin d'avant. Tests : contrôles seuls (refus, branche principale intacte, puis entrée avec un soulignement Markdown), et moteur avec un ouvrier repris qui laisse les marqueurs (aucun marqueur dans `git log -p main`).
3. **Pas de montée après une reprise de fusion.** `_suite` passe à `_apres_echec` `self._repris_hors_fusion(tache)` au lieu de `jugement.reprise`. Seule une reprise après un autre refus tient lieu de seconde chance (lu dans les passes du départ, `_passes_du_depart`). Test : deux conflits dans un départ donnent `montees == 0` et un second départ au même dosage.

Testé sur un vrai dépôt, dans les deux sens.

## 5. Doutes et demandes
- **La fusion n'est pas laissée en cours (`MERGE_HEAD`) : le résultat, marqueurs compris, devient un changement non enregistré sur la branche principale.** Trois raisons. Le test existant exige qu'`enregistrer` défasse une fusion ratée. Pendant une fusion en cours, le contrôle du périmètre et le vérificateur auraient vu le travail des autres tâches. L'historique ne garde aucun commit à marqueurs.
- **Ce qui suit le chemin d'avant.** Un fichier déclaré en « union » qui bute quand même (modifié d'un côté, supprimé de l'autre), ou qu'un motif à `*` couvre pour fnmatch mais pas pour git : la règle 1 ne reprend que les fichiers déclarés en « git ».
- **Après un échec de contrôles.** `poser_conflits` n'est appelé qu'en présence d'un motif « git ». Si la branche principale a bougé entre-temps avec un conflit, c'est ce conflit que l'ouvrier reçoit, puis les contrôles rejoués lui rendent leur sortie.
- **Les fichiers d'attributs globaux.** `-c core.attributesFile` remplace, pour les seules fusions de l'Atelier, un éventuel fichier d'attributs global de la personne ; les `.gitattributes` du projet restent prioritaires.
- **Lecture de la clé.** `fichiers_partages` est lu à l'ouverture du projet, par le moteur comme par les contrôles ; `regler_outils` ne le relit pas, pour que les deux ne divergent pas.
- **Défaut antérieur, non corrigé.** `se_chevauchent` ne voit pas qu'un chemin à crochets se recoupe avec lui-même (`app/[slug]/page.tsx`). `_premier_recoupement` n'a plus son raccourci `x == y`, pour suivre exactement la règle qui décide.
- **Tests et essais.** Aucun test ni essai existant n'a été modifié.
